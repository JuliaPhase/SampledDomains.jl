SampledDomains.SampledDomains — Module

SampledDomains attaches physical axes to arrays of data (camera images, pupils, PSFs), so that it is always clear where each element lies.

A domain is a lazy array of the points of the samples: dom[j, i] is the point (x, y) of the sample a[j, i] of an array a on the domain, returned as an SVector with the properties x and y. Nothing is stored but the description of the grid and the units.

Arrays keep the index order of images, a[j, i] with row j and column i, and by default a domain is oriented as an image read from a file: x to the right, y up, row 1 at the top (imagedomain). Then an image loaded from a file is at once the array of the values on the domain, and the REPL prints an array as the picture looks.

SampledDomains.IMAGEJ_ZERO_YORIGIN — Constant

The yorigin written instead of zero for a domain with y up and the origin on the upper edge of the image, since ImageJ takes yorigin = 0 with inverty=true as "no origin" (it then puts y = 0 one pixel above the bottom edge). In pixels; invisible in ImageJ.

SampledDomains.AbstractDomain — Type
AbstractDomain{T,N} <: AbstractArray{T,N}

A domain: the array of the points of the samples of a grid, of the size of the arrays sampled on it. A subtype defines

  • size(dom);
  • getindex(dom, I::Vararg{Int,N}), the point of the sample I, as an SVector;
  • units(dom), the units of the coordinates;

and gets iteration, map, broadcasting and linear indexing from the AbstractArray interface. Two-dimensional domains have points SVector{2,T} in the order (x, y), and the index order (j, i) of images: dom[j, i] is the point of a[j, i].

Take the coordinates of a point by name, p.x, p.y, or for (; x, y) in dom, not by position: such code does not depend on the order of the coordinates (in version 0.1 the point was [y, x]).

SampledDomains.AffineDomain2D — Type
AffineDomain2D(grid::CartesianDomain2D, map; units = units(grid))

A grid rotated, reflected, sheared, scaled or shifted with respect to the physical frame: the point of the sample [j, i] is map(grid[j, i]). grid describes the samples in their own frame (for example the pixels of a camera, in mm), and map takes a point of this frame to the physical frame. map is an AffineMap, LinearMap or Translation of CoordinateTransformations.jl; it is stored as an AffineMap with static 2×2 linear part, so that indexing allocates nothing.

Arrays on the domain have the size and index order of grid.

units are those of the physical frame, one unit for both axes (a rotation mixes them); by default the units of grid, which is right when map has no dimension (a rotation, a reflection, a stretch).

using SampledDomains, CoordinateTransformations, StaticArrays

grid = make_centered_domain2D(640, 480, 5.5e-3)          # camera pixels, mm
θ = deg2rad(30)
rot = LinearMap(@SMatrix [cos(θ) -sin(θ); sin(θ) cos(θ)])  # sensor rotated by 30°
dom = AffineDomain2D(grid, Translation(0.1, 0.0) ∘ rot)     # and shifted by 0.1 mm in x
dom[1, 1] == rot(grid[1, 1]) + SVector(0.1, 0.0)

SampledDomains.CartesianDomain2D — Type
CartesianDomain2D(xrange, yrange; units = nothing)

Rectangular grid with sample coordinates xrange and yrange. Arrays defined on it have size (length(yrange), length(xrange)), so that a[j, i] is the value at (xrange[i], yrange[j]). The domain is the array of these points: dom[j, i] == SVector(xrange[i], yrange[j]), with dom[j, i].x == xrange[i] and dom[j, i].y == yrange[j].

The ranges are taken as given. A domain oriented as an image, with y up, has a descending yrange; imagedomain and make_centered_domain2D make such domains.

units labels the coordinates: nothing (pixels, or dimensionless), a symbol such as :um, a LengthUnit, or a NamedTuple (x = …, y = …) with a unit for each axis.

dom = CartesianDomain2D(-1:0.5:1, 0:-0.5:-1; units=:mm)
a = map(p -> p.x + 2p.y, dom)            # a[j, i] = f(x[i], y[j]), size(a) == (3, 5)
a == [x + 2y for y in dom.yrange, x in dom.xrange]

SampledDomains.LengthUnit — Type
LengthUnit(name::Symbol, metres, power = 1)

A unit of the coordinates of a domain: name for the labels, metres the length of one unit, and power 1 for lengths or -1 for spatial frequencies (the dual domain). The units are a label of the domain; the coordinates stay plain numbers.

Usually made from a symbol, LengthUnit(:um), or by wavelengthunit. Known symbols: :nm, :um (also :μm, :µm), :mm, :cm, :m.

SampledDomains.SampledDomain — Type
SampledDomain(vals::AbstractArray, dom::AbstractDomain)
SampledDomain(f::Function, dom::AbstractDomain)

Values of a function on a domain: the fields vals and dom, with size(vals) == size(dom).

When constructed from a function, f is called with the coordinates of each point in their natural order, f(x, y) for a two-dimensional domain, and vals has the layout of the domain: vals[j, i] = f(dom[j, i]...), i.e. f(x[i], y[j]) for a CartesianDomain2D.

SampledDomains.dualDomain — Function
dualDomain(dom::CartesianDomain2D, q = (1, 1))

The Fourier-dual CartesianDomain2D of dom, built from dualRange, with upsampling factors q = (qx, qy) (or one integer for both), and the inverse units (μm → μm⁻¹). The upsampling keeps the frequency step 1 / (n Δx) and makes the range q times wider: it is the dual grid of an array over the same extent sampled q times finer. Zero padding, which makes the frequency step finer, corresponds instead to the dual of a larger domain with the same step.

For a domain oriented as an image (y up), the dual domain is oriented in the same way: the fftshifted FFT of an array on dom is an array on dualDomain(dom), with positive frequencies of y in the upper half.

source
SampledDomains.dualRange — Function
dualRange(xrange::AbstractRange, q::Int = 1)

Range in the Fourier-dual domain with upsampling factor q. If the sampling in x has step Δx, the dual range covers the interval [-q/2Δx, q/2Δx) with length(xrange) * q samples and step 1 / (length(xrange) Δx), in the order of fftshift: zero frequency at index length ÷ 2 + 1.

A descending xrange (negative step, as y of an image) gives a descending dual range: the frequency of the index k of an FFT is k / (n Δx), with the sign of Δx.

It is fftshift(fftfreq(length(xrange) * q, q / step(xrange))) of AbstractFFTs: each frequency is computed as k * (fs / n), correctly rounded to within one unit in the last place, and zero is exact.

SampledDomains.imagedomain — Method
imagedomain(sz::Tuple{Int,Int}; pixelsize = 1.0, origin = :center, units = nothing)
imagedomain(a::AbstractMatrix; kwargs...)

A CartesianDomain2D for an array of size sz = (rows, columns) (or of the size of a), oriented as an image read from a file: x grows to the right with the column i, y grows up, i.e. decreases with the row j; row 1 is at the top.

  • pixelsize: the steps Δx, Δy (positive), one number for both or a tuple (Δx, Δy).
  • units: the unit of the coordinates (see CartesianDomain2D).
  • origin: where (0, 0) lies:
    • :center: the geometric centre of the array; for an even size between two pixels;
    • :fftcenter: the centre of the pixel (rows ÷ 2 + 1, columns ÷ 2 + 1), where the zero frequency of fftshift lies;
    • :lowerleft: the lower-left corner of the image (the outer corner of the pixel);
    • :lowerleftpixel: the centre of the lower-left pixel;
    • a tuple (j0, i0): a fractional index; pixel (j, i) has its centre at (j, i), its corners at j ± 0.5, i ± 0.5.
img = load("camera.tif")                         # FileIO
dom = imagedomain(img; pixelsize=5.5, units=:um)
dom[1, 1]                                        # the upper-left pixel: x < 0, y > 0

SampledDomains.imagej_calibration — Method
imagej_calibration(dom::CartesianDomain2D) -> NamedTuple

The calibration of ImageJ for an image on dom: pixelwidth, pixelheight (positive), unit, yunit (nothing if as unit), xorigin, yorigin (in pixels, from the corner of the image), inverty (true for a domain with y up), wavelength (in metres, for a unit of wavelengthunit, else nothing).

The inverse is imagej_domain. With y up and the origin on the upper edge, yorigin is written as IMAGEJ_ZERO_YORIGIN instead of zero. ImageJ has no reversed x axis, so a descending xrange is an error.

SampledDomains.imagej_domain — Method
imagej_domain(path::AbstractString) -> CartesianDomain2D

The domain of the image in the TIFF file path, from its ImageJ calibration (see imagej_domain with a description). A file without the calibration of ImageJ gives imagedomain(size): no units, oriented as an image, origin at the centre. SampledDomains.imagej_domain — Method
imagej_domain(sz, description::AbstractString, pixelwidth, pixelheight) -> CartesianDomain2D

The domain of an image of size sz = (rows, columns) from the ImageDescription text of ImageJ and the pixel sizes (1 / XResolution, 1 / YResolution), as ImageJ itself interprets them, including the case yorigin = 0 with inverty=true. make_centered_domain2D(xlength, ylength, pixelsize; units = nothing)
make_centered_domain2D(xlength, ylength, pixelsizex, pixelsizey; units = nothing)

A domain of xlength × ylength samples with the given steps, centred on zero and oriented as an image (y up, descending yrange): imagedomain((ylength, xlength); pixelsize, origin = :center). SampledDomains.pointof — Method
pointof(dom, j, i)
pointof(dom, (j, i))

The point of the (fractional) index (j, i): the domain extended to real indices. For integer indices it is dom[j, i] (up to rounding). Pixel (j, i) has its centre at the index (j, i) and its corners at j ± 0.5, i ± 0.5. Used for the coordinates of features found in an image (a centroid has fractional indices).

SampledDomains.save_imagej — Function
save_imagej(path, a::AbstractMatrix, dom::CartesianDomain2D; float64 = false)

Save a as a TIFF file with the calibration of dom in the format of ImageJ (pixel size, unit, origin, direction of y; see imagej_calibration), readable by ImageJ and Fiji and by load_imagej. Needs TiffImages: using TiffImages.

Real values are saved as 32-bit floats, the type ImageJ works with. With float64 = true they are saved as 64-bit floats, and load_imagej reads them back exactly; such a file is for Julia: ImageJ 1.54 does not open it (only through File ▸ Import ▸ Raw, without the calibration), and Fiji opens it through Bio-Formats as 32 bit, with the pixel size and unit but without the origin and the direction of y.
